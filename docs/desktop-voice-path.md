# Desktop voice engines

## Decision model

The owner rejects the default Mac voice and wants Supertonic or Chatterbox. A usable voice must start quickly, keep the source character position through seek, pause and Interject, and avoid sustained memory or swap growth. Voice quality and latency are owner judgments; a successful build cannot establish them.

| Layer | Implementation | Evidence and limit |
| --- | --- | --- |
| Selection | Settings offers Mac voices, bundled Supertonic, and user-installed Chatterbox Nano or Turbo. | Activation requires explicit acceptance of the selected engine's code/model terms. Acceptance is stored per engine, and separately per Chatterbox model. |
| Supertonic | `SessionKitSupertonic` renders local chunks into WAV files. The desktop transport retains source-character ranges and prefetches one chunk. | Bundled ONNX and model assets make the debug app about 183 MB. Audible quality and sustained realtime speed remain owner checks. |
| Chatterbox | A bundled Python helper calls a user-selected local Python runtime and model directory. It uses `from_local`, reports bounded render progress, and keeps Hugging Face/Transformers offline; no runtime model download is requested. | The owner-supplied Narrate Turbo starter includes a compatible Turbo Python environment and model. The selected folder has no Nano checkpoint, and this starter's `from_local` API does not accept Nano. Nano needs both a Nano checkpoint and a Nano-compatible runtime. |
| Resource boundary | Chatterbox stays in a child process. The watchdog samples child RSS and system swap every second and terminates the process above a model-specific RSS ceiling, 512 MB of added system swap, or 90 seconds for one generation/startup. On a 16 GB Mac, Nano is capped at 2.5 GB RSS and Turbo at 5 GB RSS. The child exits if its parent disappears; Chatterbox refuses to start if swap monitoring is unavailable and fails closed if either runtime measurement fails. | Swap is a system-wide signal, so unrelated activity can trip the stop; that is safer than allowing uncontrolled growth. The process boundary cannot prove that all PyTorch/MPS allocations appear in RSS before swap changes, so both are watched. Runtime cutoff behavior still needs a bounded local check. |
| Transport | Rendered WAV chunks use `AVAudioPlayer`; its completion callback advances immediately when the next chunk is ready, rate changes use transport rate, and progress maps to the chunk's source range. The compact panel reserves one status line and truncates long messages. Slow Turbo suggests Nano only when its checkpoint and runtime validate; otherwise it points to Supertonic or Mac speech. | A slower-than-playback renderer can still leave a gap while it prepares the next chunk; progress is visible and the panel recommends an available fallback. The synthetic latency heuristic is not an objective speech-quality score. Test a long passage, two seeks, and two interjections for omissions, gaps and source-anchor drift. |

The source-range chunker is covered with Unicode and seek-offset tests. The app maps elapsed audio time within the active chunk back to source characters, then persists those offsets through pause, scrub, skip, and Interject. Automated chunk tests do not prove audible synchronization.

## Onboarding and safety

Settings links to the current [Supertonic code license](https://github.com/supertone-oss-archive/supertonic/blob/main/LICENSE) and [model terms](https://huggingface.co/Supertone/supertonic-3/blob/main/LICENSE), or the [Chatterbox code license](https://github.com/resemble-ai/chatterbox/blob/master/LICENSE) and the selected [Nano](https://huggingface.co/ResembleAI/chatterbox-nano) or [Turbo](https://huggingface.co/ResembleAI/chatterbox-turbo) model card. The owner must review and check the acceptance box before Test voice or Use. The app stores the notice revision and acceptance date separately for Nano and Turbo; changing variants does not erase the other variant's acceptance. It never checks the box itself.

The desktop package does not install Chatterbox or start it in the background. Python and model paths can be chosen in Settings. The owner's Narrate Turbo starter is detected as a prefilled path if no Chatterbox path was saved; Nano remains selected by default and the engine is not activated. The Nano and Turbo choices validate their own checkpoint files, and Settings explains when a checkpoint is missing. The worker also checks Nano API support before loading model weights. Choose Turbo to use the detected starter; a compatible Nano model/runtime has not been found on this Mac. A short voice test displays loading/render progress, and the helper's stderr log is in `~/Library/Application Support/SpokenMarginsDesktop/GeneratedSpeech/chatterbox-worker.log`.

When Chatterbox fails or exceeds a resource limit, the app stops its worker and retains the source position. A Turbo cutoff suggests Nano only when its checkpoint and runtime validate; otherwise it points to Supertonic or a Mac voice. A Nano cutoff or unavailable monitor suggests Supertonic or a Mac voice. Pause, Interject, New Text, engine changes and Quit also stop or unload the child. A missing or incompatible Python package is an onboarding error, not a reason to download dependencies inside the app.

## Verification and stopping rules

Automated checks cover acceptance revisions and resource thresholds. The desktop build verifies compilation and bundled files. The owner must accept terms and run each selected engine on their Mac before it can be called `human_validated`. During the first Chatterbox check, use a short sample and watch Activity Monitor's process memory and swap; stop after a resource cutoff or a long gap, and choose Nano or Supertonic. Do not run a long Chatterbox stress test before the short bounded test succeeds. A failing resource guard blocks Chatterbox use even if the voice sounds good.

The Chatterbox [upstream issue tracker reports Apple Silicon memory growth](https://github.com/resemble-ai/chatterbox/issues/218), and another report describes very large retained memory after a long prompt [here](https://github.com/resemble-ai/chatterbox/issues/205). These are reports, not measurements of this app. The official [Chatterbox README](https://github.com/resemble-ai/chatterbox) describes Nano as its lower-memory option; the owner's installed Turbo is larger. Supertonic's upstream [README](https://github.com/supertone-oss-archive/supertonic) identifies MIT code and OpenRAIL-M model terms.
