# Recovery MVP

## Product Promise

Spoken Margins is a personal conversational listening app. A complete daily-driver loop imports an article or podcast from the user's preferred discovery surface, plays it with native audio or the user's installed iOS voice, preserves play/pause/back/forward behavior, captures an anchored interjection, optionally summarizes eligible interjections on device, supports publisher podcast chapters and deterministic native-text Listening Maps, and exports the complete exchange for another chatbot.

The phone app has four tabs (owner's call, 2026-10-16; `Design/proposals/four-tabs.md`): Library for deliberate listening items, Following for explicit followed-feed and Quick Folder candidates, Margins for the listener's locally persisted interjections, and Settings. Source setup lives behind the shared Add Source router and continues to support pasted text, links, files, EPUBs, audiobooks, and a configured quick folder. Neither a followed-source entry nor a Quick Folder candidate enters the library until the user explicitly imports it. Now Playing is persistent session context rather than a tab.

## Compact presentation

The Library prioritizes its existing offline-rendering status and listening items over editorial chrome. Item Detail places Listening Sessions before Chapters and labels resume as **Continue**. The persistent player presents the item, chapter/progress, and existing actions without decorative artwork or a duplicate progress bar; accessibility text sizes stack the actions below the title. The full player omits the redundant Now Playing eyebrow and groups Text, Mix, sleep timer, and speed in an adaptive secondary-control layout. Mix exposes its selected state with a checkmark and accessible on/off value; existing volume and background-audio controls remain available when enabled. Native source text remains outside the transport card in the existing Text sheet. These presentation choices do not change playback, preparation, session selection, or filtering.

## Onboarding

Onboarding teaches the product's core loop before asking the user to explore intake breadth: choose one of two honestly distinct starter items, listen, save a Margin, open that Margin from the Timeline, and successfully copy or share the session export. Both starter items use production item, playback, and Timeline routes. The tour is skippable, resumable, replayable from Help.

Core progress is shown in bounded onboarding presentation that never displaces recording, import state, undo, or playback feedback. Help exposes replay and documents optional source exploration through Safari, Files, podcast links, EPUB, audiobook, pasted text, and Quick Folder; those source types do not block completion of core onboarding.

Checklist completion comes from evidence rather than self-reported taps. A saved active interjection, an explicit Timeline Margin open, and a successful clipboard/share completion satisfy the three core steps. The app reconciles interjection and typed item provenance from local persistence after relaunch. Neither seeded starter item satisfies "add one source of your own." Browser-page captures, file imports, and playable podcast resolution record distinct optional intake evidence.

The local-intelligence explanation appears after the user has reviewed an interjection. It states that Summarize Notes runs only when Apple Foundation Models are available on the device and that source material and interjections are not sent to a third-party model provider. It also states that playback, interjections, Timeline review, copy/export, pasted-response import, deterministic Listening Maps, and mapless listening remain available without the local model.

## Active Boundary

As of the owner’s September 16, 2026 decision, the app and its extensions require iOS/iPadOS 26 or later, with iOS/iPadOS 26 and 27 in the supported verification matrix. SessionKit shares the iOS 26 minimum and retains macOS 15 support. OS support does not imply Apple Intelligence eligibility, speech-model or locale availability, or sufficient resources for enhanced PDF analysis; those fallbacks remain required.

Keep the iPhone/iPad app, Safari extension, share extension, Obsidian import, native Now Playing controls, the listening Live Activity, on-device Speech.framework transcription, installed `AVSpeechSynthesizer` voices, Apple Foundation Models for scoped interjection summaries when available, generated-turn playback, interjections, publisher podcast chapters, deterministic maps from captured text structure, pasted-assistant-response import, and JSON/AI-handoff Markdown export. Native media owns Now Playing during podcasts and prepared audio; the live-speech coordinator owns it only during immediate `AVSpeechSynthesizer` playback so the two command paths do not replace each other. AVPlayer's observed transport state is authoritative after route changes or system pauses.

Exclusive playback and native Now Playing controls remain the default for every listening session. A default-off setting may expose a per-session **Mix with Other Audio** option for app-owned speech and media. Opting in uses the system's pure mixing policy, exposes only Spoken Margins' own volume in the listening screen, and relinquishes Spoken Margins Now Playing metadata and remote-command ownership for that session; it neither controls nor continuously ducks the other app. Interjection recording remains exclusive and subsequent playback restores the session's selected mixing policy.

The default Recovery MVP release hides Discuss and all bring-your-own-provider settings. One release-controlled feature flag preserves the current remote-provider/Discuss implementation for a future re-enable, but while disabled it must gate the UI, capability publication, compact and delegated commands, pending-job retries, and transport execution. A stored API key may remain local in Keychain, but no remote model request or automatic remote fallback is permitted. Users can still copy or export interjections and session context, use a chatbot of their choice, paste its response back into Spoken Margins, play that response, and interject into it.

Share intake is typed before resolution: podcast/RSS/audio URLs go to source-link resolution, while web pages, Markdown files, and text files go to text import. Browser article extraction uses the pinned, locally bundled Defuddle build with network fallback disabled and preserves Markdown headings. Pending shares import into the library without replacing the active session or screen. The Share extension confirms and dismisses after saving a handoff; it does not claim it can launch the containing app from an extension point where iOS does not support that transition. A failed share is quarantined once in Settings > Import Inbox for retry or deletion; it is not retried on every foreground activation.

Safari intake optimizes for the complete readable page. The Safari extension captures that page immediately from its toolbar action and does not expose a separate selected-text mode. Loose selected text remains available through the in-app pasted-text intake rather than making the Share or Safari extension ask the user to choose between overlapping text modes.

Cross-provider podcast handoff is an MVP discovery surface, not an optional convenience. Direct Apple Podcasts episode links, RSS/feed links, and public audio links use their stable episode or enclosure evidence. Spotify and other metadata-only links combine show, title, publisher, date, duration, and stable identifiers when available. A documented high-confidence match may import automatically; close or ambiguous candidates require a bounded user selection; a low-confidence candidate must never be silently imported. Resolution preserves both the original discovery link and the selected canonical source, imports exactly once, and never replaces active playback or navigation.

Publisher podcast chapters are intake evidence, not generated content. Ingest them in this order: Podcasting 2.0 chapter JSON, inline Podlove Simple Chapters, embedded media chapter metadata, then timestamped episode descriptions. A publisher map must navigate by source media time without requiring a transcript and must not be replaced by a lower-precedence map. Podcasts without publisher chapters remain mapless in the default MVP; future server-hosted generation stays behind the remote-provider feature flag.

Leaving the full listening screen does not stop playback. An active or paused session remains available in a persistent Now Playing bar that reopens the full player and exposes play/pause state. Transcript-backed media exposes a linear, scrubbable timeline with elapsed and remaining time plus independently configurable back/forward transport controls; both default to 15 seconds and support 10, 15, 30, 45, or 60 seconds. Text-to-speech playback retains semantic sentence, paragraph, or section navigation rather than pretending it has a media-time seek position.

When the source and its final queued generated turn have both finished, the app automatically closes the completed session, removes its player and Live Activity, and returns to the library. A system pause, route change, or interruption is not completion and must leave the session open and resumable.

Files intake accepts UTF-8 plain text, Markdown/Obsidian clips, and text-based PDFs. PDF text extraction runs off the UI actor and creates the same local text-item path; scanned/image-only PDFs remain unsupported until an explicit OCR path is added.

The listening screen supports the standard left-edge swipe back to the library without stopping audio. Transient status, error, undo, and import banners must not cover or intercept playback transport. File reads, Markdown parsing, quick-folder enumeration, audio rendering, transcription, and provider work run without monopolizing the UI actor; any operation that can outlast an immediate tap exposes visible progress while navigation and playback controls remain usable. Prepared text narration is cache-backed, so a missing generated-audio file falls back to immediate live speech and schedules regeneration instead of leaving an old text source unplayable.

Item deletion is recoverable: the user confirms moving an item to Recently Deleted, receives an Undo action, and can restore it from Settings. Moving an item preserves all item-scoped sessions, maps, transcripts, turns, and interjections. Nothing is purged automatically. Permanent deletion is available only from Recently Deleted and requires a second confirmation that names the related data that will be removed. Whole-library reset remains a confirmed developer tool, not a Home action.

An interjection detail view provides a one-action copy of that single interjection's transcript and before/after anchors. This applies equally to notes attached to the source, an interjection summary, or an imported assistant response; target-wide export remains available for multi-note handoff.

For native audio, a publisher transcript or locally derived context window is internal data used only to resolve source positions and create bounded context around an interjection. The default MVP does not transcribe a full podcast to generate a Listening Map. The app must not expose a full native-audio transcript through a view, search, clipboard, share sheet, export, portable package, or diagnostics. User-visible source-derived output is limited to source attribution, publisher Listening Map metadata, timestamps and resolved positions, and bounded before/after interjection context. The user's own interjection representations remain exportable. This conservative product boundary does not claim to settle fair-use or other legal questions.

The native-audio interjection context is a human-readable reconstruction of the listening moment: up to 90 seconds before and 120 seconds after the durable media timestamp. It is not a short machine-matching snippet. Coarse transcript segments are time-sliced to that interval, and overlapping session-export windows are merged with listener interjections embedded chronologically so size reduction never discards meaningful context.

Watch, car screens and widgets are **allowed, not scheduled** (owner's call, 2026-10-17, #2030): no thread is blocked from them by this document, and none is scheduled yet. CarPlay is the lowest priority: recording a Margin while driving is not safe, so Siri ("add a Margin", with no Shortcuts setup, even while another app plays; #126) is the way to add a Margin away from the screen, and no thread requests Apple's CarPlay audio entitlement. Home Screen widgets are welcome. The WidgetKit target is today the ActivityKit host for the listening Live Activity.

Still out of scope: MLX (Kokoro ships as a Core ML download without MLX; see #2705), arbitrary provider UI, on-device AI-generated Listening Maps, a native-audio transcript reader, or an embedded Piper runtime. Deterministic maps derived locally from source headings are intake normalization, not an AI workflow. Product-owner device evidence found podcast map generation both too slow for the MVP and capable of failing with media data outside the timeline, so AI-generated maps move to a future server-hosted feature behind the existing remote-provider release flag. Bundled Piper is a separate post-MVP investigation behind the existing speech client.

## Evidence Gates

Every core flow has three distinct states: `implemented`, `verified`, and `human_validated`. Tests and builds can establish only `verified`.

The preservation check covers installed-Piper selection, article and podcast playback, AirPod removal/reinsertion, foreground controls, background continuity, and lock-screen play/pause/back/forward. The final daily-driver check adds representative Spotify, Apple Podcasts, RSS, and direct-audio handoffs; Safari-page, Files Markdown, Safari-extension, and Obsidian intake without autoplay or session replacement; typed Add Source intake; playback continuity through Library, Sources, Margins, Item, Settings, and Export; exclusive recording; podcast scrubbing; Now Playing restoration; recoverable deletion and permanent-delete confirmation; deterministic native-text and publisher-chapter Listening Map navigation; mapless podcast fallback; podcast context around a timestamp; scoped local interjection summary; summary playback and interjection; pasted-response import/playback/interjection; Import Inbox retry/delete; AI-handoff export; and proof that remote model calls, on-device AI map generation, and full native-audio transcript disclosure are impossible in the default release profile.

Before requesting either check, provide a build number and SHA, supported device/OS, exact in/out scope, known issues, reset instructions, seeded items, diagnostics, automated evidence, and a pass/fail checklist.

## Stopping Rules

Do not advance with a crash or data-loss defect, recording-state escape, wrong-source context, wrong podcast match, wrong audio, duplicated import/turn/spoken sentence, native-audio transcript disclosure, unexpected remote model traffic, implicit import from following, protected-data deletion, fabricated metadata, or regression in preserved playback. New private-experience surfaces approved by the product owner must use existing runtime capabilities and evidence paths; provider UI and automatic AI workflows still require an explicit release-plan change. Voice runtimes and sharing follow the owner's standing calls in `AGENTS.md` (Kitten bundled, other voices downloaded; share links gated at build time and never switched on remotely).

When a human check fails, reproduce it from diagnostics, add focused regression evidence, and return only the failed bounded flow for validation. The product owner should not be used as the exploratory test harness.
