# Recipient confirmation seek correction audit — 2026-09-23

**Verdict: fail closed on rejected seeks and bind saved confirmations to exact bytes, but the paused/local-transport path still has a P1 ordering defect and the asynchronous readiness branch has a P2 gap.** The final app runtime gate remains blocked and did not execute the final app tests.

- **P1 — A paused remote session seeks the old player before switching to the local edition.** `listenAroundImportedPodcastPosition` changes the transport, issues `engine.seekMedia`, and only then resumes when paused (`Gate1AppModel.swift:7864–7876`). `SessionEngine.updatePlaybackTransport` configures context without replacing the player when status is paused (`SessionEngine.swift:329–334`); `AVPlayerStreamPlaybackClient.configureMediaContext` only updates its context (`AudioAdapters.swift:1749–1757`). The seek therefore targets the still-active remote player. Resume then calls `play` on the local URL; the adapter replaces the player and `beginMediaSeek` marks the outstanding navigation seek `media_seek_superseded` (`AudioAdapters.swift:1782–1800, 2140–2152`). The readiness gate sees failure and never arms Confirm. Reproduce with a paused session whose active stream URL differs from the validated local recipient file. Activate the local player before issuing the navigation seek, or otherwise ensure the exact seek is made against the local player after replacement. The regression uses `NoopAudioPlaybackClient`, which does not model URL/player replacement.
- **P2 — The async wait handles pending seek, but not accepted seek while playback is still starting.** The gate correctly requires the matching request to be accepted, playback status to be `.playing`, and (when available) the local URL to be active (`Gate1AppModel.swift:7923–7930`). However, the wait task is started only when resolution is `.pending` (`:7885–7913`). If the seek callback is accepted before playback reaches `.playing` or the local-URL observation catches up, the code falls directly to failure instead of waiting for the remaining readiness conditions. Continue bounded polling for accepted-but-not-yet-playing/loaded state; treat failed or superseded seek, request change, item change, generation change, and timeout as terminal. Add a deterministic test with delayed seek acceptance and delayed play readiness, plus supersession/cancellation coverage. Current coverage tests a synchronous rejected seek and a Noop client’s immediate success; it does not exercise the pending callback branch.

The new code otherwise uses a throwing `engine.seekMedia` call, arms UI confirmation only after `recipientPositionReview` is set by the readiness gate, and invalidates stale polling by generation, item, and seek ID. Rejected-seek coverage verifies Confirm stays hidden. Direct voice playback remains independent. Confirmation still rechecks the exact recipient URL/digest before atomically saving the `recipientConfirmed` result and layer digest; the persistence/reopen/edition-replacement assertions remain present.
