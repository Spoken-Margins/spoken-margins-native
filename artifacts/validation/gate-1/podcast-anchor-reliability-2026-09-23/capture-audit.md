# A–C capture audit

Bounded read-only review of `capture-handoff.md`, `baseline.diff`, the current A–C source diff, and focused regression coverage, plus the export evidence seam noted in parent spot review. No implementation changes or test/build runs. Current tree recheck confirmed the earlier aggregate-readiness and roleless-failure issues have already been corrected; they are not listed below.

1. **P1 — Capture generations are recorded but not enforced at commit.** `SessionEngine` starts the first request with `attemptGeneration: 1`, while `podcastAnchorEvidenceCompleted` and `podcastAnchorEvidenceFailed` update by Margin/session and role only. `PodcastAnchorCaptureWindow.attempt` is not compared with the callback’s request generation. Concrete race: attempt 1’s callback is queued, a retry for the same session/Margin starts and commits attempt 2, then the delayed attempt 1 callback replaces the same role/provenance artifact and marks the window committed. Carry the expected attempt generation and producing edition through completion/failure, and reject results unless they still match the durable window state. Add a controlled out-of-order app/core test; the current SQLite test covers persistence and sibling order, not stale-attempt rejection.

2. **P2 — Queue-gap invalidation is not tied to the playback generation that lost a buffer.** In `PostResumePodcastEvidenceTapContext.process`, pool exhaustion or format/copy failure queues an unconditional `invalidatePending("decoded_playback_queue_or_format_gap")` on `completionQueue`. Concrete race: a dropped callback from continuity epoch N queues invalidation behind a busy worker; a seek advances the continuity generation and a new Margin arms in epoch N+1 before the queued invalidation runs; the old invalidation then clears the new Margin’s accumulator and reports the wrong window failure. Capture the callback/continuity generations with the gap and invalidate only that epoch, or retire the epoch synchronously before admitting new requests. There is no regression test for pool exhaustion across seek/rearm.

3. **P2 — The pre-window ring signs whole buffers that merely overlap the requested interval.** `bufferedChunks(startMs:endMs:)` checks endpoint coverage, then `captureBufferedPreInterjection` signs every selected chunk unchanged. Concrete counterexample: one 20-second ring chunk from media 20s–40s overlaps a request for the 12 seconds before a 40s anchor; it passes the guards and exports a 20-second signature with a 20-second anchor offset. Near an episode edge, the same behavior can put post-anchor audio inside a purported pre flank. Trim first/last PCM buffers to `[max(0, anchor-target), anchor]` before signing, and test a chunk spanning both boundaries plus a partial edge window. The current ring test uses exact one-second-aligned buffers, so it cannot catch this.

4. **P2 — Durable state role type is broader than its schema.** `PodcastAnchorCaptureWindow.role` uses `PodcastAnchorEvidenceWindowRole`, which also has `sourceWindowBefore` and `sourceWindowAfter`; `updatePodcastAnchorWindow` and `SessionEngine.podcastAnchorEvidenceCompleted` accept and store those roles. `Contracts/schemas/interjection.schema.json` permits only `pre_interjection` and `post_resume` and caps the array at two. Concrete counterexample: integrating D’s source-window signatures through `podcastAnchorEvidenceCompleted` appends a source-window role that the strict schema rejects. Give capture-job state a pre/post-only role type, or keep reference-window outcomes in a separate model and schema.

5. **P1 — Export can silently omit acoustic evidence after the “ready” precheck.** `Gate1AppModel.exportSharedInterjections` checks only `fileExists` before export (`Gate1AppModel.swift:14292–14301`), then later drops unreadable or empty evidence with `try? Data(contentsOf:)` and `return false` (`:14328–14332`). A deletion/replacement race or a zero-byte asset therefore produces a package without that selected evidence instead of an export failure or deliberate degraded-share confirmation. Fail closed on read error/empty bytes and revalidate the exact evidence set used to build the package. Also, `shareWithoutPositioningAssurance` sets `allowsDegradedPodcastEvidence = true` (`Build23SharingSeams.swift:455`), while package mutations invalidate the preview but do not reset that consent (`:522–532`); a later changed draft can inherit consent for a different export. Bind consent to the current draft/evidence fingerprint or clear it on mutation. Add tests for deletion/empty-file after precheck and selection mutation after consent.

The review otherwise found the router forwarding both methods only on the media route, session-qualified accumulator keys, per-role asynchronous failure attribution, and SQLite persistence coverage. Remaining contract gaps explicitly acknowledged by the handoff are unsupported PCM conversion and app-side restart reconciliation; production callbacks still need the generation checks above before they can safely consume the new API.
