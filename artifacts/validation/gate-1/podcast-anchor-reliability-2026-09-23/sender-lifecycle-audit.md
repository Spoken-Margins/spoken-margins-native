# Sender B–E lifecycle audit

**Verdict: blocked on two capture-lifecycle correctness defects.** Reviewed the frozen sender snapshot `83ef297f92a95efbd860e7be7011eb19600e93851b79f2e4fb30ee38d42ba04d` against the capture-corrections snapshot and handoff. No code or tests were changed or run.

- **P1 — Reattachment can commit an unrelated later stream interval as the Margin’s post flank.** `Gate1AppModel.retryActivePodcastCaptureIfPossible` accepts any retryable post window while the same item is playing and arms it with the saved anchor; it never checks current media time, bounded interval continuity, or edition identity. `PostResumePodcastEvidenceCapture.processCopied` records the first later source time, and `finish` stores `anchorMediaTimeMs - firstMediaTimeMs` as the offset. For example, a retry for a 10-minute Margin starting at 16 minutes produces a −6-minute offset, within the archive’s permitted ±10-minute range, so it can commit as `.postResume`; an ad edit in that gap makes back-projection incorrect. **Fix:** only reattach when the current source position and provenance prove the original bounded interval, or recover from an exact-edition local source. Otherwise retain a far-away capture only as a landmark, not a flank. **Missing regression:** retry on a later/ad-edited stream must not commit as a local flank; exact-bound recovery remains allowed.

- **P1 — Foreground activation marks live capture jobs interrupted, then supersedes them.** `handleAppBecameActive` calls reconciliation with `interruptedJobs: true` on every activation; `reconcilePodcastAnchorEvidence` changes every `.waiting`, `.collecting`, or `.deriving` role to retryable failure. There is no corresponding foreground cancellation of the in-memory tap. The following `retryActivePodcastCaptureIfPossible` accepts a newer attempt, and `arm` replaces the same-key accumulator; any completed old-generation callback then fails `isCurrentPodcastCaptureAttempt`. Repeated foregrounding during a 12-second collection can consume all three attempts and mark the role unavailable. **Fix:** treat only process restoration (or a positively identified lost runtime generation) as interrupted; preserve jobs known active in this process. **Missing regression:** foreground during an active capture preserves its attempt and permits its callback to commit, while cold-start reconciliation still retries a persisted in-flight job.

**Reviewed paths without a blocker:** reconciliation keeps readable source-window/sibling evidence and the stored exact-edition digest; outcome metadata is optional/versioned, schema-constrained, path-free, and has legacy decode coverage; export fingerprints consent against reviewed selection and evidence bytes, then pins bytes and fails on read/change races. The ledger/Interjection two-save crash window can leave orphan ownership rows, but does not lose or falsely promote committed evidence; this is cleanup residual, not a correctness blocker.

The app reconciliation/export tests are compiled but not executed per the handoff; runtime verification remains pending the owner’s same-device app-plan run.
