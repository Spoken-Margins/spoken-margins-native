## Implemented in this handoff

- `Packages/SessionKit/Sources/SessionKitAudio/AudioAdapters.swift`: routed media playback now forwards both pre and post sample requests through the protocol-typed router, preserving the media result and leaving speech route isolated. The AVPlayer client queues a post request while tracks are still unknown, retries when the item becomes ready, and reports a specific failure when readiness fails. Source-clock progress checks the no-buffer watchdog.
- `Packages/SessionKit/Sources/SessionKitAudio/PostResumePodcastEvidenceCapture.swift`: pending accumulators use session-qualified Margin keys. The 20-second ring supplies the pre flank up to the original interruption anchor, including a minimum 3-second partial at the episode edge. Seek and source-time gaps invalidate pending windows. PCM buffers are copied into an eight-slot preallocated pool in the tap callback; signature work and ring management run on a serial worker. A full pool produces an explicit gap/failure. Pool and continuity generations prevent old queued buffers from re-entering a new playback epoch.
- `Packages/SessionKit/Sources/SessionKit/Models.swift`: optional, Codable per-window records retain role, anchor, attempt count, state, first failure, and latest failure. Legacy rows without them remain unknown. Independent update helpers prevent one committed flank from being cleared by a sibling failure.
- `Packages/SessionKit/Sources/SessionKit/SessionEngine.swift`: new podcast Margins persist both flank intents, then record the independent request outcomes. Evidence completion merges by role/provenance instead of replacing the sibling and preserves a known exact-edition digest when the update has none. A role-specific failure parameter is available while the old call shape remains source-compatible.
- `Contracts/schemas/interjection.schema.json`: optional capture-window structure and states.
- Focused tests in `Packages/SessionKit/Tests/SessionKitTests/{SessionKitCoreTests,SQLiteSessionStoreSafetyTests,SharingTests}.swift` cover protocol router dispatch/isolation, repeated logical IDs across sessions, SQLite reopen and out-of-order flank completion, pre-window seek behavior, and a source-progress no-buffer failure.

## API and app integration needed next

`Interjection.podcastAnchorCaptureWindows` is the durable per-flank state. Use `interjection.updatePodcastAnchorWindow(role) { window in ... }` with `accepted()`, `failed(_:retryable:)`, or `committed()` when the app handles tap, exact-local, and source-window callbacks; then save the updated Interjection under its `sessionId`. `SessionEngine.podcastAnchorEvidenceFailed` accepts an optional `windowRole`. The existing app `persistPodcastAnchorEvidence` and `markPodcastAnchorEvidenceUnavailable` still write only aggregate status, so they must be wired to these transitions. The app's evidence merge must retain `sourceExactEditionSHA256` when a later update supplies nil, as the engine now does. All callback and diagnostic lookups should use `(sessionId, interjectionId)`, not the repeated local ID alone.

An attempt/edition token must still be carried through app worker callbacks and checked before commit. Restart reconciliation, file/digest validation, transactional reference commit, cleanup pinning, explicit degraded export, independent source-window acoustic/ASR consumers, and recipient work remain outside this package handoff. The current capture adapter does not yet normalize unsupported PCM formats or implement bounded reattachment after a tap installation failure. The observed tap is verified with synthetic host PCM, not real streamed MP3 or HLS. No product flow is human validated.
